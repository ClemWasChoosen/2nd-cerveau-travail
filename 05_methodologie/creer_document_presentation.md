## 1. Avant de commencer : clarifier le cadre

Avant d'ouvrir PowerPoint ou Google Slides, répondre aux 5 questions fondamentales.

### 1.1 Les 5 questions à se poser

| Question | Pourquoi c'est crucial |
|----------|----------------------|
| **Qui sont mes destinataires ?** | Le vocabulaire, le niveau de détail et les arguments varient totalement selon l'audience |
| **Quel est l'objectif principal ?** | Informer, convaincre, former, décider... → la structure change |
| **Quel est le contexte de diffusion ?** | Oral avec présentateur ? Document lu seul ? Les deux ? |
| **Combien de temps ai-je ?** | 5 min, 20 min, 1h → le nombre de slides et la profondeur changent |
| **Quel est le livrable attendu ?** | Présentation seule ? Avec note de synthèse ? Document autonome ? |

### 1.2 Les trois modes de présentation

**Mode 1 : Présentation orale (avec speaker)**
- Slides épurés, peu de texte
- Les slides *supportent* le discours, ne le remplacent pas
- Animations et transitions utiles pour guider l'attention

**Mode 2 : Document autonome (lu sans speaker)**
- Texte plus complet, chaque slide doit se comprendre seule
- Penser à des "notes" ou une structure narrative forte
- Éviter les phrases tronquées façon "bullet point"

**Mode 3 : Hybride (présenté ET partagé ensuite)**
- Le plus courant en contexte professionnel
- Solution : slides épurés pour l'oral + annexes détaillées
- Ou : version courte pour l'oral, version longue pour le partage

## 2. Construire une structure narrative solide

### 2.1 Le principe de la pyramide de Minto (Pyramid Principle)

Développée par Barbara Minto (McKinsey), cette méthode est le standard dans le conseil et la communication professionnelle.

**Principe :** Commencer par la conclusion, puis développer les arguments, puis les données.

```
         ┌─────────────────┐
         │   CONCLUSION    │  ← Message principal (dès slide 2)
         │  / RECOMMANDA-  │
         │      TION       │
         └────────┬────────┘
                  │
    ┌─────────────┼─────────────┐
    ▼             ▼             ▼
┌───────┐    ┌───────┐    ┌───────┐
│Arg. 1 │    │Arg. 2 │    │Arg. 3 │  ← Arguments de support (3 max)
└───┬───┘    └───┬───┘    └───┬───┘
    │             │             │
  Données       Données       Données  ← Preuves, chiffres, exemples
```

**Pourquoi ça marche ?**
- L'audience comprend immédiatement où tu veux en venir
- Si on t'interrompt à mi-chemin, le message principal est déjà passé
- Facilite la mémorisation : les gens retiennent la conclusion + 2-3 arguments

### 2.2 Les structures narratives selon l'objectif

#### Structure "Décision" (Comité de direction, validation)
```
1. Executive Summary (1 slide) → Contexte + Recommandation + Impacts
2. Contexte & Problème (1-2 slides)
3. Options évaluées (1-2 slides)
4. Recommandation détaillée (2-3 slides)
5. Plan d'action & Next Steps (1 slide)
6. Annexes (données détaillées)
```

#### Structure "Information / État d'avancement"
```
1. Résumé exécutif (1 slide)
2. Objectifs rappelés (1 slide)
3. Avancement par chantier (1 slide/chantier)
4. Points d'attention & Risques (1 slide)
5. Actions & Responsables (1 slide)
```

#### Structure "Pitch / Proposition"
```
1. Le Problème (hook fort)
2. Pourquoi maintenant ? (l'urgence)
3. Notre solution
4. Preuve que ça marche (données, cas d'usage)
5. Plan d'exécution
6. Appel à l'action
```

#### Structure "Formation / Pédagogique"
```
1. Objectifs d'apprentissage
2. Contexte & Enjeux (le "pourquoi")
3. Corps du contenu (structuré en chapitres)
4. Exercices / Applications pratiques
5. Synthèse & Points clés à retenir
6. Ressources complémentaires
```

### 2.3 Le "Slide Zero" et l'executive summary

**Le slide zero** (ou executive summary) est la slide la plus importante. Elle doit répondre à :

> "Si mon audience ne regardait qu'une seule slide, que dois-je absolument qu'elle retienne ?"

**Structure type d'un executive summary :**
- **Contexte** (1 ligne) : Pourquoi ce sujet, pourquoi maintenant
- **Constat / Problème** (1-2 lignes) : Situation actuelle
- **Recommandation / Message** (1-2 lignes) : Ce que tu proposes
- **Impact attendu** (1 ligne) : Ce que ça change concrètement

## 3. Concevoir les slides : principes visuels

### 3.1 La règle du "one message per slide"

Chaque slide ne doit véhiculer **qu'un seul message**.

**❌ Anti-pattern :** Une slide avec 4 sections, 15 bullets et 2 graphiques
→ L'audience ne sait pas où regarder, le message est dilué

**✅ Bonne pratique :** Une slide = un titre-message + un élément visuel central

**Le titre-message vs le titre-label :**

| Titre-label (à éviter) | Titre-message (à privilégier) |
|------------------------|-------------------------------|
| "Chiffres de ventes Q3" | "Les ventes Q3 dépassent l'objectif de 15% grâce au segment B2B" |
| "Analyse de la concurrence" | "3 concurrents menacent notre position sur le segment PME" |
| "Options de migration" | "La migration cloud est la seule option viable à 18 mois" |

### 3.2 Les 4 éléments visuels et quand les utiliser

| Élément | Quand l'utiliser | Quand l'éviter |
|---------|-----------------|----------------|
| **Tableau** | Comparaison multi-critères, données précises | Plus de 5 lignes/colonnes sans filtre |
| **Graphique en barres** | Comparaisons entre catégories | Tendances dans le temps |
| **Graphique en courbes** | Évolution temporelle, tendances | Comparaisons ponctuelles |
| **Schéma / Diagramme** | Processus, architecture, relations | Données quantitatives |
| **Texte structuré** | Listes d'actions, principes clés | Explications longues (→ risque mur de texte) |

### 3.3 Principes de mise en page (inspirés du design)

**Principe 1 : Hiérarchie visuelle**
Tout doit avoir une taille relative claire :
- Titre slide : 28-36pt
- Titre section : 20-24pt  
- Corps de texte : 14-18pt
- Notes/Sources : 10-12pt

**Principe 2 : La règle des tiers**
Diviser mentalement la slide en 3x3. Les éléments importants se placent aux intersections.

**Principe 3 : Espace blanc = allié, pas ennemi**
L'espace blanc (vide) améliore la lisibilité. Une slide "dense" = slide illisible.

**Principe 4 : Cohérence chromatique**
- Maximum 3 couleurs (1 primaire, 1 secondaire, 1 d'accentuation)
- Utiliser la couleur pour guider l'attention, pas pour décorer
- Contraste texte/fond suffisant (ratio WCAG ≥ 4.5:1)

**Principe 5 : Alignement strict**
Tous les éléments alignés sur une grille invisible. Les désalignements visuels créent une impression de négligence.

## 4. Rédiger un contenu clair et percutant

### 4.1 Les règles de la phrase courte

**Règle d'or :** Une idée = une phrase = une ligne (si possible)

**Reformulations :**

❌ *"En raison du fait que les résultats obtenus lors de la dernière période trimestrielle se sont révélés inférieurs aux attentes initialement formulées dans le plan stratégique, il convient d'envisager une réévaluation de la trajectoire commerciale."*

✅ *"Les résultats Q3 sont sous objectif. La stratégie commerciale doit être revue."*

### 4.2 Les bullet points : bonnes pratiques

**Règle des 3-5 bullets :**
- Moins de 3 : utiliser une phrase directe
- Plus de 5 : regrouper, réorganiser, ou créer une slide supplémentaire

**Structure parallèle obligatoire :**
Tous les bullets doivent avoir la même structure grammaticale.

❌ Non parallèle :
- Augmenter les ventes B2B
- La formation équipe est importante
- Revoir le processus commercial

✅ Parallèle (verbe d'action) :
- **Développer** les ventes B2B (+20% en 6 mois)
- **Former** l'équipe aux nouvelles techniques de vente
- **Restructurer** le processus commercial en 3 étapes

### 4.3 Les données : comment les contextualiser

Un chiffre brut n'a aucun sens sans contexte.

**Les 4 contextualisations possibles :**

1. **Comparaison temporelle** : "15% de croissance vs 8% l'an dernier"
2. **Comparaison à un objectif** : "15% de croissance, objectif était 12%"
3. **Comparaison sectorielle** : "15% de croissance vs 7% pour le secteur"
4. **Projection** : "Si cette tendance continue, +45% en 3 ans"

**⚠️ Piège fréquent :** Présenter une donnée sans dire ce qu'elle implique concrètement.

Toujours finir par : *"Ce qui signifie que..."* ou *"L'impact est..."*

## 5. Adapter son message à l'audience

### 5.1 Cartographier son audience

Avant de construire la présentation, dresser un tableau d'audience :

| Segment | Expertise | Ce qui les intéresse | Ce qu'ils décident |
|---------|-----------|---------------------|-------------------|
| Direction générale | Faible sur le sujet | ROI, risques, décisions stratégiques | Validation, budget |
| Management intermédiaire | Moyenne | Faisabilité, ressources, planning | Priorisation |
| Équipes opérationnelles | Forte | Méthodes, détails techniques, impacts quotidiens | Exécution |
| Clients / Externes | Variable | Valeur apportée, fiabilité | Acheter / Adopter |

### 5.2 Le niveau de détail par audience

**Pour la direction (5-15 min, 5-10 slides) :**
- Langage business, pas technique
- Chiffres clés avec contexte
- Focus sur les décisions à prendre
- Recommandations claires avec alternatives

**Pour les managers (20-30 min, 10-20 slides) :**
- Équilibre business/technique
- Plan d'action détaillé
- Ressources nécessaires
- Risques et mitigations

**Pour les équipes techniques (30-60 min, 20-40 slides) :**
- Niveau de détail élevé
- Démos et exemples concrets
- Questions/réponses intégrées
- Annexes techniques

### 5.3 Gestion des questions difficiles

**Préparer la slide "parking lot" (Appendix) :**

Toute question prévisible à laquelle tu ne veux pas répondre en plein flux → prépare une slide en annexe.

Questions typiques à anticiper :
- "Quel est le coût ?"
- "Combien de temps ça prend ?"
- "Pourquoi pas l'option X ?"
- "Quels sont les risques ?"
- "Avez-vous des exemples comparables ?"

## 6. Les erreurs classiques à éviter

### 6.1 Erreurs de structure

| Erreur | Impact | Correction |
|--------|--------|------------|
| Pas d'executive summary | L'audience cherche le "so what" | Toujours slide 1 ou 2 |
| Conclusion à la fin seulement | 50% de l'audience a décroché avant | Pyramide de Minto |
| Trop de slides | Dilution du message, perte de temps | 1 min/slide en présentation orale |
| Pas de "Next Steps" | La réunion n'aboutit à rien | Toujours terminer par des actions |

### 6.2 Erreurs visuelles

| Erreur | Impact | Correction |
|--------|--------|------------|
| Mur de texte | Personne ne lit | Max 50 mots/slide pour l'oral |
| Trop de couleurs | Distraction, illisibilité | 3 couleurs max |
| Police illisible | Effort cognitif inutile | Sans-serif, min 14pt |
| Graphiques mal étiquetés | Mauvaise interprétation | Titre + axes + source obligatoires |
| Animations excessives | Distraction, effet amateur | 0 animation sauf si elle ajoute du sens |

### 6.3 Erreurs de contenu

- **Copier-coller depuis Excel** sans reformater → toujours refaire dans la présentation
- **Abréviations non définies** → définir au premier usage
- **Données sans source** → toujours indiquer la source et la date
- **Screenshots de qualité médiocre** → toujours recréer ou vectoriser
- **Jargon interne** devant une audience externe → utiliser un vocabulaire universel

## 7. Checklist finale avant livraison

### Structure et message

- [ ] L'executive summary est en place et complet
- [ ] Chaque slide a un titre-message (pas un titre-label)
- [ ] La structure narrative est cohérente (intro → corps → conclusion → next steps)
- [ ] Le "so what" de chaque section est explicite
- [ ] Les données sont contextualisées (comparaison, objectif, tendance)

### Visuel et forme

- [ ] Maximum 3 couleurs respectées
- [ ] Alignement des éléments vérifié
- [ ] Police lisible (sans-serif, ≥ 14pt)
- [ ] Pas de mur de texte (< 50 mots/slide pour l'oral)
- [ ] Tous les graphiques ont un titre, des axes étiquetés, une source
- [ ] Résolution des images suffisante

### Contenu et rigueur

- [ ] Toutes les abréviations sont définies au premier usage
- [ ] Les sources des données sont citées avec leur date
- [ ] Les chiffres sont vérifiés et cohérents entre les slides
- [ ] Le niveau de langage est adapté à l'audience cible
- [ ] Les "next steps" ont des responsables et des dates

### Logistique

- [ ] Nom du fichier versionné (ex: `presentation_projet_X_v2_2025-01.pptx`)
- [ ] Le fichier s'ouvre correctement sur les logiciels cibles
- [ ] Les slides s'impriment lisiblement en noir et blanc si nécessaire
- [ ] La durée de présentation estimée respecte le temps imparti

## 8. Templates de structures types

### 8.1 Template : Comité de décision (15 min)

```
Slide 1 : Executive Summary
  → Contexte (1 ligne) | Constat (2 lignes) | Recommandation | Impact

Slide 2 : Le problème à résoudre
  → Description du problème + coût de l'inaction

Slide 3 : Options évaluées
  → Tableau comparatif (3 critères max, 2-3 options)

Slide 4 : Recommandation
  → Solution retenue + justification + risques identifiés

Slide 5 : Plan d'action
  → Tableau : Action | Responsable | Deadline | Indicateur de succès

--- ANNEXES ---
Annexe A : Données de support
Annexe B : Analyse détaillée des options
Annexe C : FAQ anticipées
```

### 8.2 Template : Point d'avancement projet (10 min)

```
Slide 1 : Résumé exécutif
  → Statut global (🟢/🟡/🔴) | Message clé | 1 point d'attention

Slide 2 : Rappel des objectifs et jalons

Slide 3-N : Avancement par chantier
  → 1 slide par chantier : Réalisé / En cours / À venir / Risques

Slide N+1 : Synthèse des risques et actions en cours

Slide N+2 : Next Steps
  → Tableau : Action | Qui | Pour quand
```

### 8.3 Template : Formation (45-60 min)

```
Slide 1 : Titre + contexte
Slide 2 : Objectifs d'apprentissage (3-5 bullet points)
Slide 3 : Plan de la session

--- PARTIE 1 ---
Slide 4 : Titre partie 1 (accroche / problème)
Slides 5-10 : Contenu partie 1
Slide 11 : Synthèse partie 1 + question de compréhension

--- PARTIE 2 ---
[Même structure]

--- CONCLUSION ---
Slide N-2 : Synthèse globale (les 3-5 points clés à retenir)
Slide N-1 : Exercice / Application pratique
Slide N : Ressources complémentaires + Contact
```
